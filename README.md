# MacJanitor

MacJanitor — застосунок для macOS, який допомагає переглядати запущені процеси та знаходити файли, що займають місце на диску. Інтерфейс за замовчуванням англійською; мову можна змінити через меню **Language / Мова**.

## Можливості

- Перегляд програм і фонових процесів із показниками використання ЦП, пам’яті, PID та власника. Процеси поточного користувача можна завершити звичайним або примусовим способом.
- Окрема вкладка портів показує доступні TCP-порти, що прослуховуються, та UDP-сокети з процесом, PID і адресою; список можна шукати й оновлювати. Деякі системні процеси можуть бути недоступні без підвищених прав.
- Сканування домашньої або вибраної папки з переглядом дерева каталогів або 100 найбільших файлів. Вибраний елемент можна відкрити у Finder чи перемістити в Корзину, якщо це дозволяє політика захисту шляхів.
- Завершений результат сканування зберігається локально в `~/Library/Caches/MacJanitor/storage-scan.plist` і показується при наступному запуску разом із датою. Він може застаріти; натисніть «Пересканувати», щоб оновити його. Зупинене сканування не замінює останній збережений результат.
- Очищення вибраних журналів, кешів, Xcode DerivedData, недоступних симуляторів і Корзини. За замовчуванням файли переміщуються в Корзину; її вміст видаляється назавжди. Доступна також опція остаточного видалення інших категорій.
- Копіювання файлів і папок до Google Drive для комп’ютера. Під час перенесення оригінал переміщується в Корзину після підтвердження завантаження; якщо статус невідомий, його можна видалити вручну після перевірки.

## Вимоги

- macOS 26 або новіша.
- Swift 6 і встановлені інструменти розробника Apple для збірки.
- Для роботи з Google Drive потрібен Google Drive для комп’ютера з налаштованим обліковим записом.

## Збірка та запуск

У каталозі проєкту виконайте:

```bash
./bundle.sh
open build/MacJanitor.app
```

Скрипт збирає release-версію, створює `build/MacJanitor.app` і підписує її доступною локальною Apple Development identity. Для іншого сертифіката задайте `MACJANITOR_SIGNING_IDENTITY` перед запуском скрипта. Стабільний сертифікат і bundle identifier допомагають зберігати дозволи macOS між збірками. Застосунок також можна відкрити подвійним клацанням у Finder.

Для запуску тестів:

```bash
swift test
```

## Командний рядок

Вбудована довідка містить синтаксис, приклади, обмеження та коди завершення для кожної команди:

```bash
.build/release/macjanitor --help
.build/release/macjanitor storage --help
```

Аналогічно працюють `port --help`, `processes --help`, `cleanup --help` і `doctor --help`; довідку також можна отримати у JSON через `--json`.

Команди явних дій:

```bash
.build/release/macjanitor terminate 12345
.build/release/macjanitor terminate 12345 --force
.build/release/macjanitor cleanup --execute --category caches --yes
.build/release/macjanitor cleanup --execute --category caches --permanent --yes
```

`terminate` надсилає SIGTERM, а `--force` — SIGKILL. Доступні лише процеси поточного користувача; PID та власник перевіряються безпосередньо перед надсиланням сигналу. Успіх означає, що сигнал надіслано, а не те, що процес уже завершився. PID теоретично може змінитися між перевіркою та сигналом.

Очищення вимагає `--execute`, щонайменше одну явно вибрану `--category` та `--yes`. Без `--permanent` елементи переміщуються в Корзину; з ним видаляються назавжди. Категорія `trash` потребує `--permanent`, а очищення симуляторів через CLI не підтримується. Код `2` означає помилку, зокрема якщо частину елементів пропущено; у виводі наведено статус кожного елемента. Перед дією перегляньте кандидати через `cleanup --dry-run`.

Усі команди підтримують `--json`, наприклад `macjanitor storage ~/work --depth 2 --json`. Стандартний вивід містить один JSON-об’єкт із `schemaVersion: 1` та `command`. Помилки аргументів і виконання виводяться у stderr, а не в JSON. Код `0` означає успішне виконання, `2` — помилку чи неправильні аргументи; для `port` код `1` означає відсутність видимих збігів. Неповні результати самі по собі не є помилкою.

Поля JSON версії 1:

- `port`: `port`, `matches` (об’єкти `process`, `pid`, `user`, `address`, `state`), `limitations`. Відсутні збіги повертаються як порожній масив із кодом 1.
- `processes`: `sort`, `processes` (об’єкти `name`, `pid`, `user`, `cpuPercent`, `memoryBytes`), `limitations`. Невиміряні значення мають значення `null`; процеси можуть бути пропущені через обмеження доступу або завершення.
- `storage`: `root`, `depth`, `complete`, `directories` (об’єкти `path`, `allocatedBytes`, `complete`). `complete: false` означає неповні дані через недоступні або зниклі елементи; розмір недоступного каталогу — `null`, а доступний розмір неповного дерева — нижня оцінка.
- `cleanup`: `dryRun`, `entries` (об’єкти `category`, `path`, `allocatedBytes`, `status`), `limitations`. `allocatedBytes` дорівнює `null`, якщо розмір невідомий; статуси `incomplete`, `unavailable...` і `protected...` описують обмеження. Оцінки можуть перекриватися через жорсткі посилання.
- `doctor`: `macOSVersion`, `volume` (`path`, `availableBytes`, `error`), `developerDirectory` (`path`, `status`), `xcodeVersion`, `tools` (`name`, `path`, `status`), `limitations`. Невідомі значення — `null`.
- `apps`: `applications` (об’єкти `name`, `bundleId`, `version`, `sizeBytes`, `lastLaunchDate`), `limitations`. Розмір — оцінка з кінтейнера `.app`; дата останнього запуску невідома для процесів, що не запущені.

Локальна діагностика середовища:

```bash
.build/release/macjanitor doctor
.build/release/macjanitor doctor --json
```

Команда показує вільне місце файлової системи домашньої папки, версію macOS, обраний каталог інструментів Apple, версію Xcode (якщо її можна прочитати) та шляхи `swift`, `git`, `xcodebuild`, `clang` у `PATH`. Інструменти не запускаються: наявність шляху не підтверджує їхню працездатність, а системний shim може вимагати встановлених developer tools. `DEVELOPER_DIR`, якщо задано, визначає обраний каталог. Діагностика не змінює систему й не звертається до мережі. Код `0` означає, що звіт сформовано, навіть якщо окремі дані невідомі; код `2` — некоректні аргументи.

Попередній перегляд очищення без видалення файлів:

```bash
.build/release/macjanitor cleanup --dry-run
.build/release/macjanitor cleanup --dry-run --category caches --category brew
```

Категорії: `logs`, `caches`, `brew`, `derived`, `simcache`, `simunavail`, `npm`, `cargo`, `trash`. Вивід містить шляхи, приблизний виділений розмір та стан; недоступні елементи позначаються окремо. Недоступні симулятори неможливо оцінити без запуску `simctl`, тому їх розмір не визначається. Розміри можуть перетинатися через жорсткі посилання.

Після `./bundle.sh` CLI доступний як `.build/release/macjanitor`. Щоб знайти процес, який займає локальний порт:

```bash
.build/release/macjanitor port 3000
```

Команда показує TCP-порти в стані прослуховування та UDP-сокети, доступні поточному користувачу. Відсутність збігів не доводить, що порт вільний: інші сокети можуть бути невидимі через права доступу. Код завершення: `0` — знайдено, `1` — не знайдено серед доступних сокетів, `2` — помилка або некоректні аргументи. Плани розвитку CLI наведено в [TODO.md](TODO.md).

Найбільші каталоги за приблизним виділеним розміром:

```bash
.build/release/macjanitor storage ~/work --depth 2
```

Команда сканує всю вибрану папку, а `--depth` обмежує глибину показаних каталогів відносно кореня (за замовчуванням `1`, допустимо `0`–`100`). Результат включає сам корінь і відсортований за розміром у байтах. Якщо деякі елементи недоступні або зникли, відповідні каталоги й їхні предки позначаються `incomplete`, а в stderr виводиться попередження; такий результат є нижньою оцінкою. Код `0` означає завершення сканування, `2` — неправильні аргументи або недоступний кореневий каталог. Символічні посилання не обходяться; розмір жорстких посилань враховується один раз, тому він може приписуватися лише одному з каталогів.

## Доступ до диска

Без повного доступу до диска деякі папки недоступні, тому результати сканування можуть бути неповними. За потреби відкрийте **Системні параметри → Приватність і безпека → Повний доступ до диска**, додайте `MacJanitor.app` і ввімкніть доступ. У вкладці «Сховище» також є кнопки для відкриття налаштувань і повторної перевірки доступу.

Сканер показує приблизний виділений простір вибраної папки, а не загальний зайнятий або вільний простір диска. Він не обходить символічні посилання і враховує жорсткі посилання один раз. Недоступні або зниклі під час сканування елементи позначаються як такі, що мають невідомий розмір; вони не додають невідомий обсяг до суми. Системні дані, інші папки, знімки диска й очищуваний простір можуть пояснювати відмінності від показників macOS.

Перед остаточним видаленням перевірте вибрані категорії: цю дію неможливо скасувати. У режимі Mirror Google Drive перенесення файлу може не звільнити місце на диску.

Перегляд найбільших процесів за пам’яттю або ЦП:

```bash
.build/release/macjanitor processes --sort memory --limit 10
.build/release/macjanitor processes --sort cpu --limit 10
```

Пам’ять — фізичний footprint у байтах. ЦП вимірюється між двома вибірками протягом однієї секунди; 100% відповідає одному завантаженому ядру. За сортуванням за пам’яттю ЦП не вимірюється; невиміряні показники виводяться як `unknown` або `null` у JSON. Деякі процеси можуть бути пропущені через права доступу або завершення. За замовчуванням показано 10 процесів за пам’яттю; допустима межа — від 1 до 10000.
